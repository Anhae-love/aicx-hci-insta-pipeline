## 오늘 확인한 것 (사실 관계)

### 1. 대시보드는 이미 라이브다 — 정상 작동 확인
- GitHub Pages 배포 성공, 실제 브라우저로 열어 눈으로 확인함.
- 설계한 7개 블록 **전부 정상 렌더링**:
  상태 pill(검토 대기) / 제목·출처 / 카드 6장 / 캡션·NOTES 접이식 /
  사람 확인 체크박스 4개 / 승인·반려 버튼 / 지난 이력 테이블(19건).
- 처음에 "manifest 안 읽힘"으로 보였던 건 **WebFetch(텍스트 요약 도구)의 길이 한계**였고,
  실제 발행 파일은 210,954바이트 완전한 유효 JSON. 브라우저에선 멀쩡히 뜬다.

### 2. PC와 저장소의 구조가 다르다 (중요)
| | PC 실제 폴더 | GitHub 저장소 |
|---|---|---|
| 구조 | 평면: `automation/ output/ logs/ state/ docs/` | 분리: `code/ data/ docs/` |
| .git | **없음** (저장소와 연결 안 됨) | 당연히 있음 |

- 지금 저장소 내용은 다른 챗이 **파일을 수동 재배치해 한 번 올린 스냅샷**이다.
- **PC는 저장소와 연결돼 있지 않다.** → 현재 구조로는 매일 자동 갱신이 **불가능**.

### 3. 반려 기록은 지금 허공으로 사라진다 (구멍)
- 대시보드 반려 버튼 = 결정 JSON을 화면에 보여주고 **"복사"까지만**. 정적 페이지라 저장 못 함.
- PC `state/`에도 반려 기록 파일 없음 (index.jsonl, last_run.json 둘뿐).
- 기획실(pipeline_prompt)이 과거를 읽는 건 `state/index.jsonl`뿐 =
  "이미 쓴 주제/색/오브젝트 중복 방지용". **"사람이 왜 반려했는지"를 읽는 경로가 없다.**
- 즉 교수·동료 피드백 2(사람 접근)·3(측정 루프)·4(가드레일)가 가리키던 구멍이 여기다.
  "반려 → 기획실 반영" 루프가 설계는 됐지만 **아직 연결 안 됨**.

  (--clipboard / --inbox / --json, 중복 방지)
- `build_manifest.py`: decisions 읽어 각 콘텐츠에 결정 부착 + metrics(승인율·최근 반려사유)
- `index.html`: **측정 루프 지표 섹션** + 이력 테이블 '사람 결정' 열

## 아직 안 된 것 / 다음에 (PC 앞에서)

### PC 연결 — clone (docs/PC연결_안내서_clone.md 그대로)
1. `git clone … insta-pipeline` (기존 폴더 옆 새 폴더)
2. **resvg.exe 복사**: 기존 폴더 automation/bin/resvg.exe → 새 폴더 code/automation/bin/
   (3.4MB 바이너리라 공개 저장소엔 일부러 안 올림)
3. config.json 의 claude_path·codex_path 확인
4. `.\code\automation\run_daily.ps1 -DryRun` 으로 경로 재배치 검증
5. `.\code\automation\setup_task.ps1` 로 스케줄러를 새 폴더로 교체 (옛 작업 중복 확인)
6. 진짜 실행 1회 → 로그에 "대시보드 push 완료" 확인
- ⚠️ PC는 아직 **평면 구조 + .git 없음** 그대로다. clone 하면 새 폴더가 분리 구조+git 연결로 생긴다.
- ⚠️ ps1 3개는 PowerShell 문법을 이 세션에서 실행검증 못 했다(pwsh 없음). DryRun 이 첫 실검증.
