# 인스타 HCI 파이프라인 — 완성 정리 (2026-10-19)

> 이 문서 하나로 "오늘 뭐가 완성됐고, 매일 어떻게 돌고, 뭘 하면 되는지" 다 안다.
> 저장소: `Anhae-love/aicx-hci-insta-pipeline` · 대시보드: https://anhae-love.github.io/aicx-hci-insta-pipeline/

## 1. 지금 상태 — 완전 자동으로 도는 하루 사이클

```
🌙 새벽 3~5시   PC가 카드 6장 제작 (조사→facts→content→자가검사→GPT검증→렌더)
                └ 감사·검증 게이트 통과한 것만 awaiting_human_review
☀️ 아침 7:10    클라우드가 결과를 GitHub에 업로드 + 폰 푸시 알림 + 보고
                └ 대시보드(폰) 자동 갱신
🧑 낮           폰에서 검토 → 승인 or 반려
                └ 반려 시: 결정 복사 → decisions.inbox 에 저장
🌆 저녁 9시     21시까지 미검토면 자동 보류(expired_no_review)로 넘어감 (가드레일)
🔁 다음 새벽    기획실이 최근 반려 사유를 읽고 오늘 기획에 먼저 반영 (측정 루프)
```

사람이 하루 안 봐도 멈추지 않고, 사람이 반려하면 그 이유가 다음 콘텐츠에 반영된다.

## 2. 폴더·스케줄 구조 (중요)

### PC에 폴더가 둘
| 폴더 | 역할 |
|---|---|
| `인스타 프로젝트 야르~` | 기존 원본 (평면 구조, git 없음) — **백업, 안 씀** |
| `insta-pipeline` | 새로 clone (code/data 분리 + git 연결) — **이게 운영 폴더** |

### 저장소 구조 (교수님 코드/데이터 분리)
```
insta-pipeline/
├─ code/           코드 (automation, prompts, tools, config)
├─ data/           데이터 (output, logs, state, metrics, image_tests)
├─ docs/           대시보드 (index.html, data/manifest.json, cards/)
└─ .github/workflows/pages.yml   docs push 시 Pages 자동 발행
```

### 스케줄 (전부 새 폴더 기준)
| 작업 | 시각 | 하는 일 | 어디서 |
|---|---|---|---|
| HCI 인스타 일일 콘텐츠 | 새벽 3~5시 | 카드 제작 + manifest 갱신 | PC |
| HCI 인스타 가드레일 | 저녁 21:00 | 미검토분 자동 보류 | PC |
| AICX 인스타 결과 → GitHub 자동 업로드 | 아침 7:10 | PC→GitHub 업로드 + 푸시 알림 | 클라우드 |

**업로드·푸시는 클라우드 작업 하나가 전담.** PC는 카드 제작 + manifest 갱신만 (중복 push 제거).

## 3. 오늘 완성한 것

### 대시보드 (이미 라이브, 구성 100% 확인)
상태 pill / 제목·출처 / 카드 6장 / 캡션·NOTES / 사람 확인 체크박스 4개 /
승인·반려 / **측정 루프 지표** / 이력 테이블(검증=기계 + **사람 결정** 열).

### 반려 → 기획실 측정 루프 (구멍 메움)
- 그동안 반려는 "복사"까지만 하고 **아무데도 저장 안 됐다.** 이게 구멍이었다.
- `collect_decision.py` — 결정을 `data/state/decisions.jsonl` 에 기록 (클립보드/인박스/직접, 중복 방지)
- `build_manifest.py` — 결정을 읽어 승인율·반려사유 지표 + 이력 '사람 결정' 열 생성
- `pipeline_prompt.md` 0단계 — 최근 30일 반려 사유를 읽고 **다음 기획에 먼저 반영**
- → 반려 테스트로 끝까지 작동 확인함 (rejected 1, 승인율 0%, 반려사유 표시)

### 사람 부재 가드레일
- `guardrail.py` — awaiting_human_review 인데 당일 21:00 지나고 결정 없으면
  STATUS=expired_no_review 로 보류, decisions 에 {decision:expired} 기록.
  `--within-days 2` 로 최근 것만 (과거 안 건드림).
- `run_guardrail.ps1` + PC 21:00 스케줄 등록.

### 구조 통일 (code/data)
- PC를 새 폴더로 clone → 분리 구조 + git 연결.
- `verify.py`·`run_daily.ps1`·`setup_task.ps1`·`pipeline_prompt.md` 경로를 분리 구조에 맞춤.
- resvg.exe(렌더용, 공개 저장소 제외)는 기존 폴더에서 복사.
- git user 신원 설정 → 자동 push 작동 확인.

### 재사용 스킬
- `pipeline-review-dashboard` 스킬 저장됨 (이 패턴 전체를 다음 프로젝트에 재사용).

## 4. 매일 사람이 하는 일 (딱 이것만)

1. 아침 푸시 알림 받으면 → 폰에서 대시보드 열기
2. 카드 6장·캡션·NOTES 보고 → 체크박스 4개 확인
3. **승인**이면 인스타에 올리기 / **반려**면:
   - "결정 복사" → 메모장에 붙여 `insta-pipeline\data\state\decisions.inbox\아무이름.json` 으로 저장
   - (다음 새벽 자동 흡수. 즉시 반영하려면 `python code\automation\collect_decision.py --inbox`)
4. 21시까지 못 보면 → 가드레일이 알아서 보류 처리

> 반려 JSON은 **대시보드에서 복사한 것**을 쓰면 인코딩 안 깨진다.
> (PowerShell 콘솔은 한글이 깨져 보여도 파일 내용은 정상 — 화면만 그런 것)

## 6. 파일 지도 (code/automation/)

| 파일 | 역할 |
|---|---|
| `pipeline_prompt.md` | 기획실 — 매일 뭘 만들지 (0단계에 반려 반영 규칙) |
| `verify_prompt.md` + `verify.py` | 감사실 — GPT 교차검증 게이트 |
| `render.py` | 카드 렌더 (SVG→PNG, resvg) |
| `build_manifest.py` | 대시보드 인덱스 + 측정 지표 생성 |
| `collect_decision.py` | 사람 결정 수집 (decisions.jsonl) |
| `guardrail.py` | 미검토 자동 보류 |
| `run_daily.ps1` | 새벽 파이프라인 러너 |
| `run_guardrail.ps1` | 저녁 가드레일 러너 |
| `setup_task.ps1` | 스케줄러 등록기 |

## 7. 아직 안 한 것 (급하지 않음)

- 측정 루프를 **더 풍부한 지표 대시보드**로 (지금은 승인율·반려사유. 반응·조회 등 추가 여지)
- 클라우드 업로드 작업이 **새 폴더를 정확히 읽는지** 내일 첫 실행으로 검증
- (선택) 기존 백업 폴더를 `_백업_구버전` 으로 이름 바꿔 정리
